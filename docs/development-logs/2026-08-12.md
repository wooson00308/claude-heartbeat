# 2026-08-12 개발 기록

## 자동 배정 dispatcher와 런타임 0.9.0

- 범위: 자동 배정 마스터 상태, 읽기 전용 자격 대기열, `no_target` 정상 대기, 파일 watcher, 공정 배정, schema v5, 30일 기록 보존, 서비스 전환·복구, 모델 진단 계약.
- 결정: 작업 대기열은 작업 ID를 선예약하지 않고 매 판정 시점의 전체 자격 결과를 사용한다. 실제 lease는 실행 직전 원자 예약에서만 잡는다. 대상 없음은 실행·오류·quota·provider 호출을 만들지 않는다.
- 서비스: launchd/systemd/Task Scheduler는 `agent-dispatcher`를 실행한다. macOS 외부 heartbeat plist는 수정하지 않고 비활성화하며, 관리 서비스 설치 실패 시 원래 enabled/loaded 상태를 복구한다.
- 실기 결함: launchd 강제 재시작은 이전 프로세스의 `finally`를 건너뛰어 dispatcher DB 행을 남겼다. 새 프로세스가 OS PID/생성 신원을 확인해 gone·PID 재사용 행만 조건부 해제한 뒤 소유권을 인수하도록 수정했다. 테스트가 띄운 실제 detached dispatcher도 `finally`에서 종료하도록 보강했다.
- 패키징: v0.9.0 macOS universal2 one-folder 런타임을 생성했고 Python, psutil, watchdog 네이티브 모듈의 arm64/x86_64 slice와 manifest를 확인했다.
- 실기 검증: 관리 서비스가 앱 stable launcher를 사용하며, `launchctl kickstart -k` 뒤 PID와 DB 소유권이 함께 새 PID로 이동했다. 앱 종료 뒤에도 서비스가 running 0.9.0으로 유지됐다. 외부 `com.catze.dream-heartbeat.plist`는 전환 전후 SHA-1 `2c7b580d806341e840ea92cc8079d03bb4092741`로 동일했다.
- 검증: `pytest -q` 330 passed, 8 skipped. 변경 범위 Ruff 통과. 원격 태그·릴리스는 만들지 않았다.
- 남은 위험: Linux·Windows 서비스는 정의와 자동 검사를 통과했지만 이 macOS 기기에서 실제 OS smoke를 실행할 수 없다. 공식 target CI에서 최종 산출물 양성 경로를 확인해야 한다.

## 런타임 0.9.1 Linux 호환 릴리스 교정

- 범위: 앱 Ubuntu 22.04 릴리스에서 `GLIBC_2.38 not found`로 거절된 Linux standalone 런타임의 빌드 기준 교정.
- 결정: 이미 공개된 v0.9.0 산출물은 바꾸지 않고 v0.9.1을 새로 발행한다. 일반 테스트·wheel smoke runner는 유지하고, 배포되는 Linux standalone 패키지의 CI/release matrix만 Ubuntu 22.04로 고정한다.
- 변경: 런타임 버전을 0.9.1로 올리고 두 workflow의 Linux package runner를 Ubuntu 22.04로 고정했다. 두 workflow가 호환성 하한을 유지하는 회귀 검사를 추가했다.
- 검증: `pytest -q` 335 passed, 8 skipped; 변경 파일 Ruff, compileall, diff check 통과. 저장소 전체 Ruff에는 이번 변경과 무관한 기존 경고 11건이 남아 있다.
- 후속: GitHub 3OS package CI와 v0.9.1 release service smoke 통과 후 앱 v0.1.12에 해당 런타임을 결합한다.
